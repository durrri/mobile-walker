# R9 deterministic variable river width

`WorldRiverOwner` now retains the single immutable full-water-width profile for its accepted final spine. The versioned flow is seed → macro spine → regional meanders → final spine → width profile → carving, water, terrain strips, placement relationships, gameplay, and bridges. Width lookup is linear interpolation on a global arc-length lattice and never depends on chunks or caches. Production contexts receive the profile explicitly and reject missing or spine-mismatched products; there is no object-identity registry or fixed-width fallback. The exported reference world lazily owns a normal generated profile solely for its long-lived compatibility fixtures.

The target is the 4 wu base width multiplied by continuously blended `sampleBiome` weights (mountain .78, highlands .88, forest/lake 1, plains 1.15, wetland 1.30), a seeded aperiodic ±6.5% value-noise field, and measured final-spine bend response capped at +18%. Lake is intentionally transitional: lake basins remain separate logic and cannot inflate the channel. Long biome smoothing and the explicit 0.035 wu/wu gradient limit avoid steps and pulsing.

Safety generation densely resamples the final spine and discovers non-local pairs through a bounded spatial index. Conservative endpoint caps enforce the pair half-width sum plus 2 wu dry neck, corrections are reduction-only feathered for 12 wu, and gradient limiting only reduces values so it cannot reopen an overlap. Final interpolated validation rejects an impossible configured minimum rather than re-expanding it. The profile reports targets, components, accepted values, and clamped count. Width configuration is immutable and included in owner identity; world generation is version 9 while persisted player-state schema is unchanged.

Banks use a bounded hybrid: the authoritative water half-width varies, while the 1.25 wu bank and 2.25 wu terrain falloff remain fixed. This preserves narrow-reach shoreline structure without making wide lowland falloffs excessive. Water mesh frames, terrain carving and strips, relationships/gameplay, and bridge bank anchors all sample the same profile. Debug remains presentation-only and lazy; the retained profile contains plain numeric diagnostics but no debug geometry.

Detailed debug mode lazily builds at most 128 accepted-width cross-sections, target/accepted profile readout values, and safety-clamp markers. Ribbon and off modes allocate none of these records or meshes, and mode transitions dispose each resource once. Debug state never participates in generation.

R9 is symmetric. Strong bends receive modest measured-geometry widening, not outer-bank erosion or inner point bars. Width supplies a canyon-like regional signal in rugged biomes but does not add vertical canyon generation or hydrological guarantees.

## Fresh Node benchmark

The post-R9 diagnostic (10 samples, nearest-rank p95) measured dry cold generation at 186.514 ms median / 217.475 ms p95 and cached lookup at 0.001 / 0.015 ms. River chunks measured: diagonal 673.493 / 829.860 ms, canyon 657.053 / 818.260 ms, bridge fixture 615.555 / 688.969 ms, and POI-adjacent 514.920 / 563.729 ms. Gameplay queries measured 0.044 / 0.204 ms and safe-position searches 8.519 / 15.389 ms. A separate 20-sample profile-generation run, including its indexed topology correction and final validation, measured 5.075 ms median / 15.648 ms p95. Terrain triangulation was the largest river-chunk synchronous stage (487.765 ms diagonal median); dry chunks remained dominated by POI/bridge generation (121.518 ms median). These values are machine-local diagnostics rather than iPhone Safari guarantees. The existing R7/R8 benchmark did not retain a directly comparable width-generation stage, so no unsupported percentage comparison is claimed.
